# dsh-harmony-watch

鸿蒙手表上的 DeepSeek Harness（DSH）轻量客户端，也能通过自己的 API Key 独立在线对话。DSH 遥控模式支持看模型动作、发指令、审批提权、切会话和模型；独立模式由手表直接请求 HTTPS API，不需要 DSH 宿主持续运行。首次打开有五页上手引导。

当前版本：手表 **2.1.7**，宿主插件 **2.1.0**。

> A HarmonyOS watch client for DeepSeek Harness, with crown-adaptive controls and standalone HTTPS API chat. Configure manually or scan a short-lived setup link from your phone. API chat runs directly on the watch; the DSH host is only needed for remote control and optional QR setup.

## 组成

```
鸿蒙手表 App ──HTTP/轮询──▶ dsh-harmony-watch 插件（跑在 DSH 进程里）
                              ├── 6 位配对码（24 小时有效）
                              ├── 审批转发（先于 Web UI）
                              ├── 工具/回复事件流
                              ├── 指令下发（followup / steer）
                              ├── 会话列表与恢复
                              ├── 当前会话模型切换
                              └── 图片消息（按需拉原图）
```

- `watch-app/`：鸿蒙工程（ArkTS，API 20+，WATCH 系列圆屏）
- `host/`：DSH 插件，零依赖，只用 Node 内建模块
- `scripts/`：一键安装脚本

## 快速开始

### 1. 装插件

```bash
./scripts/install.sh web      # macOS / Linux
powershell -File scripts/install.ps1 web   # Windows
```

脚本会装插件、备好 cloudflared，并打印后续配置提示。装完重启 DSH。

### 2. 装手表 App

用 DevEco Studio 或自己的工具链编译 `watch-app/`，签名后侧载到手表。

### 3. 配对

启动日志里会打印 6 位配对码和外网地址；手机浏览器打开 `http://127.0.0.1:8765/pair` 也能看。

手表连接页填地址和配对码，配对码一天内有效。

手表第一次启动会先显示五页引导，讲完再进配对页；不想看可以直接「跳过」，之后在「菜单 → 使用引导」里还能重看。

## 独立 API 对话

未配对也可从连接页点「独立 API 对话」。进入工作台后，从「控制中心 → 会话」新建或继续本地 API 会话；API 名称、地址、Key 和模型在「控制中心 → API 设置」管理。多余的「独立对话」菜单入口已移除。API 聊天与 DSH 当前会话、审批和模型选择相互独立，不会把消息发给 DSH。

### 在手表填写

1. 在独立 API 设置中填写 **HTTPS API 地址、模型名、API Key**。
2. 选择 **Chat Completions** 或 **Responses** 协议。例如 DeepSeek 可以填写 `https://api.deepseek.com/v1`、`deepseek-chat` 和 Chat Completions；模型权限以自己的服务商账号为准。
3. 点「保存并返回」并确认，进入与 DSH 共用的主聊天页，点底部「发消息」。此后即使 DSH 宿主关闭，手表联网即可直接对话。

在「控制中心 → 会话」中，本地 API 与 DSH 会话显示在同一列表，各自标明来源；选中项有勾选标记。会话列表支持表冠和触摸滚动，居中最大、上下收小，使用懒加载避免一次渲染所有会话。可分别新建本地或 DSH 会话，本地会话可以二次确认删除。API 设置只负责模型、Key 和扫码，不再单独开一套聊天窗口。

完整的 `/chat/completions` 或 `/responses` 地址也可输入，程序会规范化，避免重复拼接路径。API 地址不接受 URL 内嵌账号、密码、查询参数或片段。

### 手机扫码填写

1. 更新宿主插件到 **2.1.0 并重启 DSH 引擎**，手表先完成 DSH 配对。
2. 独立 API 设置 →「手机扫码配置」，手机浏览器扫码后填写上述字段。
3. 提交后回到手表，**核对 API 地址、模型与协议，点「保存并返回」并再次确认**。手机提交不会自动开启 API 请求。

二维码是五分钟、一次性的配置链接，不含 API Key 或 DSH 长期配对令牌。Key 仅在宿主内存临时中转，领取、取消、到期或插件卸载时清除，不进入事件流或文件。配置好之后，聊天不再经过宿主。手机与手表必须能访问同一个宿主地址；优先使用 HTTPS。HTTP 局域网配置有窃听和篡改风险，只在可信网络使用，不要分享二维码。

### 本地保存与范围

- 按用户选择，2.1.3 起 API Key **明文保存在手表应用私有空间**，不再因 HUKS 不可用而只保留到进程结束；输入仍隐藏，Key 不进入 URL、界面摘要或日志。最多保存 30 套 API 配置（总计 1 MiB），每套有独立名称、网址、Key、模型和协议。
- 更新先尝试读取旧单配置并迁移，成功写入新快照后也不删除旧加密副本；读取或解密失败时明确提示并保留原数据，可继续新增、稍后重试迁移。保存新配置不先清空旧 Key，只有明确确认删除指定条目才删除该 API。
- 独立会话、成功的消息历史、未发送草稿和选中会话继续单独保存在手表本地，关闭 App、重启、修改或删除 API 都不会删除聊天记录。聊天与 API 文件均是明文私有存储；**卸载或清除应用数据仍会丢失**，尚无导出备份。
- 最多 30 个本地会话、总快照 4 MiB；每会话保留最近 100 条完整消息（50 轮），单次请求只携带最近有界上下文。超出总量时明确报错，不自动删除其他会话。
- 发送前先保存草稿；失败或停止保留输入供重试，不重复加入历史。回复收到但存盘失败时，主输入栏提供「重试保存回复」，只重试写盘，不再次请求 API。停止本地请求不保证服务商立即停止计费。
- 主聊天底部「模型」胶囊会弹出已保存 API 的选择小窗，展示名称、模型和网址，绝不展示 Key。不同配置即使网址相同也有独立 ID，会话记录其配置绑定；选另一套配置或修改地址/模型会保留旧会话并进入新会话，不偷偷转发旧历史。旧配置已删除时，历史仍可阅读，不能猜另一个账号的 Key 自动续聊。
- 当前使用非流式文本请求，等待完整回复后显示；不包含图片、多模态、工具执行或 DSH Agent 能力。
- **WorkBuddy / Codex 账号登录未接入**：本轮未能核实适用于第三方手表客户端的官方授权条件，不提供仿冒登录、Cookie 导入或借用其他客户端身份的入口。API Key 模式不等同于这些产品的订阅登录。
- 新 UI、直连 API、多配置迁移与真实表冠手感仍需 HUAWEI WATCH 6 实机验证；构建和本地模拟测试不能替代实机。

## 手表端功能

- **上手引导**：第一次打开时自动进入，五页讲清配对、左右切屏、发指令、审批和停止；可以跳过，之后从「菜单 → 使用引导」重看
- **圆屏表冠列表**：控制中心、快捷页、统一会话列表共用 64vp 大胶囊和懒加载；居中最大、上下收小，首尾也能居中。控制中心与快捷页删除了滚动提示，标题作为透明、不拦触摸的浮层，列表可经过标题后方
- **表冠边界回弹**：到顶或到底继续转动时呈现有界阻尼拉伸，松表冠后回弹；连续转动不反复重启动画，触摸接管和离场会清理回弹。此实现是模拟的视觉弹性，不代表与系统触摸回弹使用同一套原生物理参数，手感仍需实机验证
- **滑动返回**：子界面不再显示返回按钮。系统边缘右滑与页面中央的明确右滑走同一套导航历史，回到来源页；例如菜单进设置后回菜单，扫码页先回 API 设置。输入编辑时先收起焦点，避免横向选字触发退出；主界面三屏横滑仍保留，只有真正根界面允许系统退出 App
- **独立 API 对话**：手表直连自己的 HTTPS API，支持 Chat Completions / Responses、手动/手机扫码配置，与 DSH 共用主聊天气泡和输入面板；多会话及草稿本地持久化，支持恢复、停止、新建和删除
- **沉浸阅读**：纵向拖动聊天时，标题和状态点向上淡出，消息/停止/模型操作层向下淡出；松手或手势取消后淡入恢复，不等待惯性滚动结束。表冠滚动同样支持，停止后恢复。普通点按、横向翻页、自动滚到底和模型/输入浮层不触发隐藏；隐藏期间按钮不接收误触
- **稳定聊天视口**：聊天列表永久占满主聊天页；标题/状态放在顶部，消息/停止/模型放在底部，上下操作层不再绘制整片背景，仅保留按钮自身底色；位置、淡出动画和主聊天表冠修复维持不变。用全高纵向容器和弹性空白定位，避免把内容 align 误当成 Stack 子项定位。内容首尾保留固定安全余量，隐藏动画不改变列表高度、inset 或偏移。底部翻页白条仍保留原有独立区域和逐帧跟随逻辑，未改成可能被原生 Swiper 遮挡的覆盖层
- **主聊天表冠**：使用不随顶栏淡出移动的独立 Text 焦点入口，触摸后、唤醒或关闭输入/模型窗后归还焦点；主聊天根节点做带页面条件的冒泡兜底，处理后阻止继续冒泡。聊天列表有顶部留白，原生偏移可能为负，使用相对 `scrollBy`，避免非动画 `scrollTo` 将负目标归零；其他列表维持原逻辑
- **三屏滑动**：菜单 / 对话 / 快捷三页横向切换，底部指示条通过原生逐帧位置跟随拖动与松手动画
- **会话流**：文字回复完整显示；工具调用、执行结果收成一行，点开看完整参数/输出；消息按左右气泡分列
- **图片消息（实验性）**：宿主会把图片元数据推给手表，但手表端渲染还没调通，目前可能看不到；文字消息、表情字符正常
- **审批**：主机请求提权时自动切到审批页，允许 / 拒绝；超时交还电脑
- **模型切换**：列表按服务商分组，切换后提示「下一轮生效」
- **停止**：两段式确认，第一下只是变红，3 秒内再点才真正中断
- **通知**：App 不在前台时，回合结束或出现新审批会发系统通知；诊断页可以测试通知、看后台状态
- **诊断**：菜单 → 诊断，看当前地址、链路、轮询间隔、失败次数、事件/会话数，可清空本地缓存
- **断线重连**：失败后按 2s → 4s → 8s → 16s → 30s 退避，连上立刻回到 2s

## 远程连接

插件默认 `tunnel: auto`，按顺序选择：

1. **局域网**：同一 Wi-Fi，填 `IP:8765`，零配置
2. **cloudflared 快速隧道**：没配置时自动下载并拉起，地址每次重启会变
3. **固定隧道**：配置 `tunnelToken` 和 `remoteUrl`，地址不变
4. **frp**：`tunnel: frp` 加 `frpServer` 等四项，需要自己的服务器和 frpc

手表会记住内网、外网两个地址。设置里可选「自动 / 内网 / 外网」：自动模式走外网时每 30 秒探测一次内网，回到同一 Wi-Fi 自动切回。

## 配置

改 profile 的 `cordis.patch.yml`，给 `dsh-harmony-watch` 加字段：

```yaml
- id: dsh-harmony-watch
  name: dsh-harmony-watch
  config:
    port: 8765
    tunnel: auto
    pairingTtlMs: 86400000
    # tunnelToken: <Cloudflare 隧道 token>
    # remoteUrl: https://你的域名
    # frpServer: 你的服务器
    # frpRemotePort: 6000
```

## 桌面端兼容性

代码不依赖 Android 或 proot，路径走 `os.homedir()`，子进程走 `spawn`。插件用的 DSH 服务：

`agents` / `sessions` / `agentPresets` / `agentDefaultModel` / `sessionPersistence` / `sessionTitle`，模型切换额外用 `sessionController` 和 `llm`（拿不到就明确失败，不影响其他功能）。

目前只在 **Android 版 dsh-go 的 proot 环境**（DSH 0.2.1-rc.4）实机验证过，没有在 Windows / macOS 桌面端测过。已知风险：

- Windows 下 cloudflared 下载与路径处理
- 桌面端防火墙首次放行 8765
- 不同 DSH 版本的服务接口差异，缺服务时会降级或报错

## 已知限制

- 快速隧道地址会变，长期使用建议固定隧道或 frp
- 图片显示是实验性的：`/api/image` 已能在宿主侧取到原图，手表端 `Image` 加载仍未验证通过（2.0.9+）；被 offload 出会话的旧图无法再取
- 审批卡片只展示工具名和原因摘要
- 穿戴设备不支持长时后台任务（`startBackgroundRunning` 返回 9800005），退后台后靠系统「延迟挂起」维持轮询，额度（通常几分钟）用完会暂停；长时间离开手表时通知可能收不到
- 后台通知还依赖系统允许通知，手表开了勿扰也不会响
- 引导的「已看过」标记存在手表本地偏好里，清除应用数据后会再出现一次
- 手表需侧载，签名和安装流程因设备而异
